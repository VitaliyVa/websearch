# Нотатки по проєкту — для себе майбутнього

README описує, **як користуватись**. Цей файл — про те, **що вже коштувало часу** і
чого з коду не видно. Читати перед тим, як щось міняти.

## 1. Що це

Конвеєр пошуку лідів: знаходить у США бізнеси, власники яких україно- або
російськомовні, у яких застарілий сайт (або сайту нема), оцінює їх і віддає
продажникам у Google-таблицю та веб-панель.

Замовник продає сайти. Отже **лід = бізнес, якому є що переробляти**. Сучасний
сайт — не лід, навіть якщо власник стовідсотково свій.

## 2. Правило №1: квота — це реальні гроші

Google Places оплачується з живого білінгу. Безкоштовний ліміт місячний, і за
ним одразу починається оплата. Замовник просив явно: **за межі не виходити**.

```
text_search     1000/міс   (Enterprise SKU, $35/1000 далі)
place_details   1000/міс   (Enterprise + Atmosphere, ~$40/1000)
psi            25000/день  (безкоштовно завжди)
```

**Чому Text Search дорогий.** Здається, що це Pro SKU з 5000 безкоштовних. Ні:
щойно в `fieldMask` потрапляє `websiteUri`, `rating`, `userRatingCount` або
`nationalPhoneNumber` — запит білиться як **Enterprise**, і безкоштовних стає
1000. Без цих полів пайплайн не працює, тож 1000 — реальна стеля.

**Захист — тільки програмний.** Виставити ліміт на боці Google на споживчому
акаунті неможливо (`COMMON_QUOTA_ORG_QUOTA_CONSUMER_NOT_ALLOWED_FOR_LOCATION`).
Тому [src/quota.ts](src/quota.ts):

- лічильник у `.quota-ledger.json` **поза `data/`** — видалення бази не обнуляє витрати;
- списання **до** мережевого виклику, не після;
- платні витрати вимагають і прапорця, і `ALLOW_PAID_SPEND=yes` у середовищі.

**Що безкоштовне і чим варто користуватись сміливо:**
завантаження будь-якого сайту напряму, скріншоти через Playwright, PSI.
Ручний розбір 47 кандидатів (розділ 8) не коштував жодного виклику Google.

Стан на 2026-08-04: `text_search 709/1000 · place_details 445/1000 · psi 486`.
Ліміти оновлюються 1 вересня.

## 2b. Правило №2: у таблиці ЖИВА робота менеджерів

З 2026-08-05 продажники працюють у панелі щодня. На момент запису — **44
проставлені статуси** у двох людей. Це змінює ціну помилки: зламана вкладка
чи затертий статус — не «перезапустимо експорт», а втрачена робота людей.

**Що це забороняє:**

- ставити тестові статуси в живих вкладках (для тестів є `Rejected` або
  окремий рядок, який одразу прибирається);
- міняти склад машинних колонок без міграції та оновлення Code.gs;
- вважати, що `rescore` безпечний «бо він лише в базі» — сам по собі так,
  але наступний `export` рознесе наслідки по вкладках.

**Що вже захищено (і перевірено наскрізним тестом):**

| Ризик | Захист |
|---|---|
| Експорт затре статуси | пише лише в `A:W`, людські колонки `X:AA` не чіпає фізично |
| Лід переїхав між вкладками | нотатки переносяться разом із ним |
| Пайплайн відхилив опрацьований лід | рядок **лишається** з попередженням у описі |
| Змінилось сортування | ключ `place_id`, номери рядків можуть їхати як завгодно |
| Двоє тиснуть одночасно | `LockService` у Apps Script |

Останній пункт з'явився не одразу: `rescore` переводив лід у `rejected`,
вкладки `Rejected` у таблиці немає, рядок вичищався разом зі статусом.
Нотатки збиралися перед очищенням, але відновлювати їх було нікуди.
Перевірка — `scripts/test-note-survival.ts`: пише статус у живу таблицю,
примусово відхиляє запис, ганяє експорт, звіряє, відновлює стан.

## 3. Конвеєр

| Стадія | Команда | Коштує квоти |
|---|---|---|
| L1 пошук місць | `npm run discover` | text_search |
| L2 аудит сайтів | `npm run audit` | ні |
| L3 мова з відгуків | `npm run reviews` | place_details |
| L4 швидкість | `npm run lead -- psi` | ні |
| L5 експорт | `npm run export` | ні |
| переоцінка з кешу | `npm run lead -- rescore` | **ні** |
| перефільтрація | `npm run lead -- refilter` | **ні** |

`rescore` і `refilter` — головні робочі коні. Змінив правило → прогнав по кешу →
побачив ефект, нічого не витративши. Спочатку правило, потім `rescore`, і лише
якщо результат подобається — нові виклики.

## 4. Модель даних

SQLite (`node:sqlite`, вбудований у Node 24 — навмисно, щоб не збирати нативні
модулі під Windows). Таблиці: `places`, `site_audits`, `owner_scores`,
`review_signals`, `psi_results`, `screenshots`, `api_usage`, `sheet_rows`.

**Бакети** (`places.bucket`):

- `leads` — готові для продажника
- `no_site_lead` — сайту немає, але мова підтверджена → вкладка «Ліди без сайту»
- `upsell` — мова підтверджена, але сайт СУЧАСНИЙ → вкладка «З хорошим сайтом»
- `manual` — потребують людського ока
- `pending` — чекають на мовний сигнал з відгуків (коштує квоти)
- `no_site` — сайту немає, мова не підтверджена
- `rejected` — відсіяні; запис і причина лишаються, ніщо не видаляється

Три перші бакети — це три **різні оффери** одному й тому ж типу клієнта:

| Бакет | Стан сайту | Що продаємо |
|---|---|---|
| `leads` | застарілий або не працює | новий сайт |
| `no_site_lead` | немає взагалі | перший сайт |
| `upsell` | сучасний | SEO, реклама, підтримка, доробки |

`upsell` з'явився після зауваження замовника, і це була моя помилка
класифікації: я відхиляв такі бізнеси як «сайт сучасний», хоча власник свій,
а бізнес живий. Не відсів, а інший оффер.

Обидва бакети без придатного сайту сортуються за **мовним скором**, а не за
оцінкою сайту: там або сайту немає, або він добрий за визначенням, тож
впорядковує список саме впевненість у власнику.

`manual_verdict` — окрема колонка (див. розділ 5). Не плутати з `bucket`:
`bucket` перераховується щоразу, `manual_verdict` — ні.

Причина будь-якого переміщення пишеться в `places.reject_reason` — назва
історична, насправді туди йде причина і для переведення **в** ліди теж.

## 5. Де ухвалюються рішення

### `decide()` — [src/commands/audit.ts](src/commands/audit.ts)

Єдина функція вердикту. Її кличуть `audit`, `rescore`, `reviews`, `enrich`.

#### Перше правило: вердикт людини понад усе

> **Ручний розбір без цього безглуздий.** З 28 рішень, ухвалених після
> перегляду 47 кандидатів, наступний `rescore` скасував **26**. Joong Boo
> Market, відхилений як корейський супермаркет, спокійно повернувся як
> «мовно підтверджений».
>
> Причина: рішення писалось у `bucket`, а `bucket` перераховується щоразу.
> Тепер вердикт живе в окремих колонках `manual_verdict` /
> `manual_verdict_reason` / `manual_verdict_at`, і `decide()` при ньому
> виходить одразу. Знімається через `clearManualVerdict()`.
>
> Ставити через `setManualVerdict()`, НЕ через `setBucket()`.
> Перевірка: 92 закріплені записи переживають повний `rescore` — 0 скасовано.

**Пастка при закріпленні:** скрипт, що вже поставив бакет, легко пропустить
запис через `if (p.bucket === m.to) continue` — і рішення лишиться
незакріпленим. Звіряти треба з `manual_verdict`, а не з `bucket`.

> **Це вже двічі ставало джерелом однакової помилки.**
> `cheapFilter` працює лише при вставці. Будь-яке правило, перевірене тільки
> там, обходиться переоцінкою, і відсіяне воскресає:
>
> - церкви й консульство України повернулись у ліди після `rescore` → довелось
>   продублювати `excludeTypes` у `decide()`;
> - «Ukraine-Moldova American Enterprise Fund» (1 відгук) і «U.S.-Ukraine
>   Business Council» (3) сиділи в Лідах, бо `decide()` не перевіряв мінімум
>   відгуків. Виправлення перекласифікувало 229 записів.
>
> **Додаєш фільтр — додай його в `decide()`, інакше він працює лише один раз.**

**Третій обхід того самого:** бакет `no_site` через `decide()` не проходить
взагалі — `audit` бере лише місця з сайтом. Тому 906 із 909 не мали ані
мовного скору, ані перевірки на некомерційність. Обидва тепер рахує
`scripts/score-nosite.ts`. Якщо додаси правило, що має діяти на всіх — не
забудь і цей шлях.

**Четвертий:** `rescore` пропускав усе без кешованого HTML — а нечитані сайти
кешу не мають. Але **назві кеш не потрібен**, тож 833 записи не діставали
розширень лексикону: «Varenyk House» (287 відгуків), «Beryozka European
Market» (277), «Meest-Karpaty» (156) стояли з нулем, хоча детектор їх упізнає.
Тепер для таких є окрема гілка, що рахує вердикт із наявних даних.

### `scoreSite()` — [src/score/quality.ts](src/score/quality.ts)

Повертає бал 1-10, причини і `status`: `ok | dead | blocked | no_site`.

`dead` ≠ `blocked`, і плутати їх дорого:

- `dead` — сайт справді не відкривається. Чудовий лід, лишається в Лідах.
- `blocked` — нас не пустили. За челенджем може стояти свіжий React, тож іде
  на ручну перевірку, а мовний сигнал тут ні до чого (він рахується з назви й
  відгуків, а не з недоступної сторінки).

`datedMarkers` — ознаки застарілості, **незалежні від швидкості**. Швидкість —
асиметричний доказ: повільний сайт точно поганий, а швидкий не доводить нічого.
Примітивна сторінка 2012 року вантажиться за 0.4 с і отримує PSI 95. Саме тому
рішення «чи вартий заміни» спирається на маркери, а не на підсумковий бал.

### `scoreOwner()` — [src/score/owner.ts](src/score/owner.ts)

Мовний скор. Пороги в пресеті: `ownerScoreLead` 55, `ownerScoreManual` 40.

**Гіпотеза, яка не справдилась:** `languageCode` у відгуках Google. 0 з 44 місць
повернули щось окрім `en` — діаспора в США пише відгуки англійською. Вагу
перенесено на **імена рецензентів** (до 60) замість мови тексту (25).

## 6. Розпізнавання імен

[src/detect/](src/detect/) — найтонша частина, 189 тестів. Основне:

- **Польська діаспора в Чикаго більша за українську.** Суфікси `-ski/-sky`
  прибрано, є список польських прізвищ. `-ak` теж прибрано — Nowak.
- **`sz`, `cz`, `w` СВІДОМО не нормалізуються.** Bondarczuk польський,
  Bondarchuk український — саме написання несе сигнал.
- **Англійська Вікісловникова база засмічена транслітераціями** (Boyko, Bondar,
  Tkach там є). Тому курований список прізвищ має пріоритет над словником.
- Модель ексклюзивності: `exclusive | shared | foreign | unknown`.
- Суфікси перевіряються на **сирому** токені: нормалізація вбиває сигнал
  (Gordovskiy → gordovski).

### Лексикон назв бізнесів

Побудований з **реальних назв у базі**, не з уяви. Головна закономірність:
діаспорні бізнеси в США масово беруть за назву звичайне побутове слово в
транслітерації — `Stolovaya` (1213 відгуків), `Skovorodka` (981),
`Gastronom` (674), `Selo`, `Beriozka`, `Hetman`, `Matreshka`, `Borshch`.
Носій англійської так бізнес не назве, тому сигнал дуже чистий.

Інші групи: кирилиця прямо в назві (найсильніший сигнал, 35);
«European deli/market» — стандартне брендування слов'янських продуктових;
однозначні транслітерації імен (`Aleksandr`, а НЕ `Alexander`; `Dmitriy`,
а НЕ `Dmitri` — інакше ловляться «Roman Auto Body» і «Aaron's Movers»);
пострадянські російськомовні громади (Центральна Азія, Кавказ) — окремою
нижчою вагою з явною міткою, бо для продажу це та сама аудиторія.

### Власна класифікація Google — найдешевший сигнал

`places.primary_type` буває `ukrainian_restaurant`, `russian_restaurant`,
`eastern_european_restaurant`, `georgian_restaurant`. Це **не здогад із назви,
а мітка самого Google** за меню й відгуками. По базі таких 47 місць.

Дані приходять у тій самій відповіді Text Search, за яку вже заплачено —
**додаткових викликів нуль**. Ми просто довго їх не використовували.

Рахується в `typeSignal()` і **додається** до балу за назвою, а не замінює
його: у «Veselka» назва не каже нічого, а тип каже все; у «Beryozka European
Market» навпаки — назва промовиста, а тип звичайний `grocery_store`.

### Дефекти, знайдені лише переглядом виводу очима

1. **Цикл маркерів брав перший збіг, а не найсильніший.** Через це
   `European Market & Deli "Beryozka"` отримував 22 за загальне «європейське»
   і ніколи не доходив до «Beryozka» вагою 28. Тепер береться максимум —
   але НЕ сума, інакше назва з трьома маркерами вистрелить у стелю.
2. **Написання.** У лексиконі був `beriozka`, але не `beryozka`. Перевіряй
   нові слова на кількох транслітераціях і на вигаданому слові поруч
   (`Brezka` не повинно ловитись).
3. **Кінцева межа слова `\b` у групі префіксів.** «European Delicatessen»
   (1178 відгуків) давав нуль: після збігу «European Deli» іде «c», і `\b` не
   спрацьовував. Слова тут навмисно зіставляються за префіксом —
   deli/delicatessen, grocer/grocery. Обов'язково перевіряй, що правило не
   перебирає: «European Wax Center», «European Auto Repair», «European
   Autohaus» мусять лишатись на нулі.

### Що знання ринку дає понад детектор

27 лідів переведено вручну після особистого перегляду черги. «Veselka» — не
слово зі словника, а легендарний український ресторан на 2-й авеню з 1954.
«NetCost Market» узагалі не має слов'янських ознак у назві, але це мережа
російських супермаркетів у Брукліні на шість точок.

Критерій при цьому лишається подвійним: власник + сайт. Фільтр відкинув
«Veselka Grand Central» (сайт 7/10) і «Gurman Trucking» (10/10, інший бізнес
зі схожою назвою).

## 7. Панель і Apps Script

Статика на GitHub Pages + бекенд усередині таблиці.

**Чому не ключі в браузері.** Будь-який ключ у статиці публічний: DevTools →
Network → і стороння людина має приватний ключ service account. Пароль у
статиці, де дані вже в бандлі, лише малює форму.

Тому Apps Script: код виконується на боці Google, ключів у браузері немає
взагалі. Межа захисту чесна — хто знає URL і код, той зайде. Для списку
комерційних лідів достатньо.

**Дві неочевидні речі:**

- POST іде з `Content-Type: text/plain` навмисно. Apps Script не обробляє
  CORS-preflight, а `application/json` його викликає. `text/plain` вважається
  простим запитом і проходить.
- Код доступу в `sessionStorage`, не `localStorage`. Закрив вкладку — вийшов;
  на спільному офісному комп'ютері це має значення.

**Розкладка таблиці:** `A..W` машинні, `X..AA` людські. Межа береться з
`MACHINE_COL_COUNT`, ніде не зашита буквою.

> Apps Script шукає людські колонки **за назвою заголовка**. Раніше там стояло
> `COL_STATUS = 23`; коли додали «Опис для продажника», усі людські з'їхали на
> одну вправо, і скрипт почав писати статус поверх опису — мовчки, при кожній
> зміні.
>
> Міняєш склад колонок → `npm run sheet:migrate` (вставляє колонку зі зсувом
> даних через `insertDimension`, нотатки не губляться) → **онови Code.gs у
> редакторі й розгорни НОВУ ВЕРСІЮ**. Без нової версії Google віддає стару.
> URL при оновленні існуючого розгортання не змінюється.

**Вкладки віддаються СПИСКОМ**, а не фіксованими полями `{leads, manual,
noSite}`. Apps Script читає всі аркуші, крім службових (`SERVICE_TABS`), а
панель малює стільки кнопок, скільки прийшло. Тому **додавання вкладки в
пайплайні більше не вимагає лізти в редактор Apps Script** — саме через це
довелось перерозгортати при появі «Лідів без сайту».

Панель приймає **обидва формати** (`normalize()` у `web/src/api.ts`). Це не
надмірність: панель і бекенд оновлюються нарізно — скрипт вставляється в
редактор руками, — і між викоченнями є вікно, коли працює стара версія. Без
сумісності менеджери в цей момент бачили б порожній екран.

### Розгортання Apps Script

```
Оновлення:  вставити код → Ctrl+S
            → Розгорнути → КЕРУВАТИ РОЗГОРТКАМИ → олівець
            → Версія: НОВА ВЕРСІЯ → Розгорнути
```

**Збереження ≠ розгортання.** Поки не створено нову версію, Google віддає
попередню, і зміни просто не видно — найлегший спосіб згаяти пів години.

«Новий розгорток» НЕ використовувати: він видасть іншу URL, яку довелося б
міняти і в `web/.env`, і у змінній `APPS_SCRIPT_URL` на GitHub. Оновлення
наявного розгортання зберігає URL.

Перевірка, що поїхала нова версія — маркер, **унікальний для нового коду**.
Зараз це наявність поля `tabs` у відповіді; раніше — колонка «Коментар», яку
стара версія не діставала, бо читала рівно 26 колонок.

**Скріншоти** лежать у `web/public/shots/` і їдуть у збірку (`npm run shots`).
Панель не може дістатись локальних файлів, а Drive відпадає: service account на
споживчому акаунті не може створювати файли (`storageQuotaExceeded`).

## 8. Пастки, що вже коштували часу

### Дані й фільтри

1. **`regionCode: 'US'`** змушує Google прибирати «USA» з `formattedAddress` —
   фільтр адреси відкинув усі 559 місць. Тепер перевірка за кодом штату + ZIP.
2. **Bot-protection з кодом 2xx.** `moskalenkogroup.com` віддає HTTP 202 і 168
   байт челенджу. Аудит зарахував це за справжню сторінку й приписав
   «не адаптивний». Ознака тепер — тіло < 2 КБ без `<title>`.
3. **«Сайт», який насправді Instagram або eBay.** Три ліди мали профіль замість
   сайту. Це не поганий сайт, це `no_site` — інший оффер.
4. **Два різні бізнеси з однаковою назвою.** `cdek.ru` (відхилено) і
   `cdekus.com` (американський). Масові операції за назвою — тільки з
   перевіркою на кількість збігів.
5. **Хибні спрацювання детекторів, знайдені лише звіркою тексту з фактами:**
   `/checkout` збігався зі скриптом Stripe і робив юрфірму магазином;
   «Sun Berry» з назви бізнесу зараховано як прізвище власника;
   `uniquePageTypes` рахує перший сегмент шляху, тож «плоский» сайт із 50
   сторінок давав «46 різних макетів».
6. **Google не позначає громадські заклади організаціями.** «Ukrainian
   Cultural Center» має тип `cultural_center`, «Ukrainian National Home» —
   `corporate_office`. Обидва проходили повз `excludeTypes` і з кирилицею в
   назві очолили б список. `cultural_center` додано; решту довелось прибрати
   руками — типів на всі випадки не вистачить, тому верх списку варто
   переглядати очима.
7. **Мовний сигнал ≠ етнічність власника.** Joong Boo Market (4647 відгуків)
   має робочу версію `?lang=ru` — але це корейський супермаркет, який
   *обслуговує* російськомовних. Робоча `/ru` доводить намір говорити з
   аудиторією, а не походження власника.

### Інструменти

6. **PowerShell псує UTF-8.** `Get-Content -Raw` + `Set-Content -Encoding utf8`
   подвійно кодує кирилицю. Файли з українськими рядками правити тільки Edit/Write.
7. **`tsx` + `page.evaluate()`.** esbuild дописує іменованим функціям хелпер
   `__name`, якого немає в браузері. 45 із 47 замірів мовчки вмерли, повернувши
   порожнечу. Тіло для `evaluate` передавати **рядком**.
8. **Робочий каталог Bash зберігається** між викликами. Один `cd web` — і всі
   наступні відносні шляхи їдуть.
9. **`gh` недоступний** у середовищі Bash-інструмента. Наглядач за деплоєм на
   ньому мовчки провисів 13 хвилин.
10. **Катастрофічний бектрекінг регулярок** — три окремі зависання: вкладені
    таблиці в `detectTech`, пошук email по inline-base64, прогрес у пайп-буфер.
    Скрізь тепер стеля на обсяг сканування.

### Панель

11. **`Selector` пише в таблицю сам.** Отримавши `value`, якого немає серед
    `options`, він «виправляє» його і викликає `onChange` на монтуванні — одне
    відкриття панелі тихо переписало два ліди. Два запобіжники: зміна, рівна
    поточній, у мережу не йде; невідомий статус стає окремим варіантом.
12. **Рядки-привиди.** Очищення рядка мусить стирати і `place_id` — панель
    показує будь-який рядок із ключем. Плюс окремий прохід звірення з реальним
    вмістом аркуша: осиротілі рядки з минулих прогонів у `sheet_rows` не значаться.
13. **Вкладка `Meta` має 2 колонки** — `loadCells` на всі 27 падає з
    «Out of bounds». Читати людські колонки тільки з вкладок лідів.
14. **XDS потребує `reset.css` + `astryx.css` і обгортки `<Theme>`.** Без них
    компоненти рендеряться зовсім без стилів. CSS 0.37 КБ проти 128 КБ — надійна
    ознака, що стилі не підключені.
15. **Дати з Sheets приходять серійним числом** (`46238.54`), коли їх записав не
    Apps Script. Форматувати перед показом.
16. **Ліміт на зображення в контексті.** Читати десятки скріншотів підряд не
    вийде — з певного моменту API відхиляє їх усі, незалежно від розміру.
    Тому для масового огляду треба **вимірювані** ознаки (прийоми верстки,
    заголовок сторінки, наявність кирилиці), а очі берегти для звірки вибірки.
17. **Мерехтливі заглушки їдять CPU.** 58 `Skeleton` під ліниві зображення
    анімувались одночасно, зокрема за межами екрана. Лікується одним
    `content-visibility: auto` на картці — браузер пропускає рендер невидимого.
18. **Назва вкладки живе у ТРЬОХ місцях:** сам аркуш, прив'язка `sheet_rows`
    і мапа `tabKey` в Apps Script. Змінити лише конфіг — це осиротити старий
    аркуш і змусити експорт вважати, що всі рядки переїхали, тобто вичистити
    їх разом із нотатками. Перейменовувати аркуш через API і оновлювати
    `sheet_rows` в одному заході. Доказ успіху: `+0 нових, N оновлено`.
19. **Мітки в панелі не можна вішати лише на ключ вкладки.** Ключ формує
    Apps Script, і для невідомої йому вкладки повертає автоматичний слаг —
    тож нова вкладка лишається без мітки, доки скрипт у редакторі не оновлять.
    Звіряти і за ключем, і за назвою.
20. **Позиціювання накладок міряти, а не вгадувати.** Мітка «ukr/ru» заввишки
    20 px при зсуві -7 закривала 13 із 32 px кнопки — рівно текст. Один замір
    `getBoundingClientRect()` замінює три ітерації «трохи вище».

## 9. Метод: не вір заміру, поки не звірив

Найдорожчий урок. Для ручного розбору я зробив шкалу «віку дизайну» за
прийомами верстки. Перша версія дала **збіг 2 з 11** з тим, що я бачив очима, і
всі оцінки виявились однаковими — через пастку №7 замір не зібрав нічого.

Після виправлення — **9 з 11**, обидва розходження впритул до порогу.

**Звідси правило:** будь-яка нова метрика спершу перевіряється на вибірці, де
відповідь відома незалежно. І діяти можна лише на краях шкали — сіру зону
лишати людині.

Те саме стосується перевірок деплою: `grep` на рядок, який є і в старій версії
(`content-visibility` є всередині XDS; «Складність розробки» є як ключ колонки),
дає хибне «готово». Маркер має бути **унікальним для нового коміту**.

### Негативний результат, який варто не повторювати

**Браузер не пробиває Cloudflare.** 626 записів мають нечитаний сайт, з них
365 — HTTP 403. Гіпотеза була, що за ними ховаються слов'янські сайти.

Перший замір дав «30 із 40 відкрилось» — і був **хибний**: сторінка челенджу
«Just a moment…» важить ~270 символів і за розміром тексту не відрізняється
від справжньої. З очікуванням, поки заголовок перестане бути челенджем:

```
40 проб → 19 челендж не пройдено · 5 мережевих помилок · 10 прочитано
з 10 прочитаних слов'янських: 0
```

Справжній Chrome із профілем (`channel: 'chrome'`, `launchPersistentContext`)
кращий за вбудований Chromium — 5 із 15 проходять самі. Але 514 унікальних
доменів роблять ручне проходження безглуздим: топ-100 доменів покривають лише
172 записи, і серед них Kaiser Permanente, Firestone, Extra Space Storage.

За челенджем справді сидить NetCost Market — але його впізнали за назвою,
а не за сайтом.

## 12. Побажання замовника, які легко забути

- Тільки США. Росія й Білорусь виключені (домени `.ru/.by/.su`, телефони `+7`).
  Але **білоруський чи узбецький бізнес У США — свій**: він російськомовний,
  а це те, що визначає оффер.
- Церкви, НГО, консульства, культурні центри — **не шукати**. Сайти вони не
  купують, а мовний сигнал у них ідеальний, тож вони забивають верх списку.
- Мінімум 5 відгуків: поріг живості бізнесу.
- **Ніколи не виходити за безкоштовні ліміти без явного дозволу.** Це було
  сказано прямо і не змінювалось.
- Питання про обхід лімітів (нові акаунти, картки менеджерів) виникали двічі.
  Відповідь та сама: це порушення умов Google, під ризиком усі пов'язані
  акаунти, а економія — $57 за метро при $0.60 за лід. Не варте того.
- Спілкування українською. Комміти й код — англійською.
- Наприкінці задачі — оцінка часу для середнього мідла без AI.

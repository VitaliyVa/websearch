# Панель лідів для продажників

Статичний сайт для GitHub Pages. Читає ліди з Google-таблиці, дозволяє
фільтрувати, сортувати й міняти статус — зміни одразу летять назад у таблицю.

---

## Головне про безпеку — прочитай перед налаштуванням

Статичний сайт **не має сервера**. Усе, що потрапляє в бандл або в мережевий
запит із браузера, — публічне. Тому:

- **JSON-ключ service account сюди класти не можна.** Будь-хто відкриє DevTools,
  забере приватний ключ і отримає доступ до всієї таблиці.
- **«Пароль» у чистій статиці нічого не захищає**, якщо дані вже лежать у бандлі.

Тому бекендом працює **Apps Script**, який живе всередині самої таблиці:

```
браузер ──код доступу──► Apps Script (виконується в Google) ──► Таблиця
   ▲                          │
   └────── дані ──────────────┘
```

Ключів у браузері немає взагалі. Код доступу перевіряється на боці Google.

**Чесна межа захисту:** URL веб-застосунку публічний. Хто знає URL і код —
зайде. Це рівень «замок від чесних людей», якого достатньо для списку
комерційних лідів. Для персональних даних клієнтів потрібен був би OAuth.

## Налаштування, 5 хвилин

### 1. Бекенд

1. Відкрий таблицю → **Розширення → Apps Script**
2. Встав вміст [`apps-script/Code.gs`](../apps-script/Code.gs) замість того, що там є
3. Заміни коди в `ACCESS_CODES` на свої:
   ```js
   var ACCESS_CODES = {
     'твій-код-олег': 'Олег',
     'твій-код-ірина': 'Ірина',
   };
   ```
   Окремий код на кожного — тоді видно, хто саме змінив статус, і можна
   відкликати доступ одній людині, не міняючи пароль решті.
4. **Розгорнути → Новий розгорток → Веб-застосунок**
   - Виконувати від імені: **Я**
   - Хто має доступ: **Усі**
5. Скопіюй URL вигляду `https://script.google.com/macros/s/…/exec`

### 2. Локальний запуск

```bash
cd web
cp .env.example .env      # встав туди URL з кроку 1
npm install
npm run dev
```

### 3. Деплой на GitHub Pages

1. У репозиторії: **Settings → Pages → Source: GitHub Actions**
2. **Settings → Secrets and variables → Actions → Variables → New variable**
   - ім'я: `APPS_SCRIPT_URL`
   - значення: URL з кроку 1
3. Запуш у `main` — [workflow](../.github/workflows/deploy-web.yml) збере й розгорне сам

## Що вміє панель

**Три вкладки** — `Ліди`, `Ручна перевірка`, `Без сайту`.

**Графіки** (Recharts) рахуються з тих самих даних, без окремих запитів:
- воронка статусів кільцем — одразу видно частку неопрацьованих
- розподіл оцінки сайту: зелене = поганий сайт = гарячий лід
- топ міст і ніш

**Фільтри й сортування** — пошук по назві, сайту, телефону й доказах мови;
фільтр за містом і статусом; сортування «найгірший сайт спершу».

**Статус просто в картці.** Зміна пишеться в таблицю миттєво, ім'я продажника
проставляє сам Apps Script за кодом доступу — випадково записати чуже не вийде.

**Деталі ліда** — докази мови, техстек, PSI, оцінка годин, соцмережі.

## Поділ колонок

Правило успадковане з пайплайна і працює в обидва боки:

| Колонки | Хто пише |
|---|---|
| A..V | пайплайн (`npm run lead -- export`) |
| W..Z | продажники через цю панель |

Панель **читає** A..V і **пише тільки** W..Z. Пайплайн ніколи не чіпає W..Z.
Тому перезапуск експорту не затирає нотатки, а панель не ламає машинні дані.

Пошук рядка йде за `place_id`, а не за номером: номер змінюється щоразу, коли
експорт перевантажує таблицю з іншим сортуванням.

## Обмеження Apps Script

| | |
|---|---|
| Викликів на добу | 20 000 |
| Час на виконання | 6 хв |
| Кеш відповіді | 60 с |

Для 5 продажників і кількох сотень лідів — із великим запасом. Кеш прибирає
більшість звернень до Sheets, тож панель лишається швидкою.

Одночасні записи захищені `LockService` — двоє продажників не перезапишуть
один одного.
